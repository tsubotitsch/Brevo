# Brevo PowerShell Module - Copilot Instructions

## Project Overview

Brevo is a PowerShell 7.0+ module that wraps the Brevo REST API v3 (digital marketing platform). It provides 67 cmdlets for managing contacts, email campaigns, domains, users, and Sales CRM (notes, deals, companies, tasks). It follows the **Sampler/ModuleBuilder** framework — a standardized PowerShell module build pattern that merges source files into a distributable module artifact.

## Key Commands

### Build & Development
- **Full build**: `./build.ps1 -ResolveDependency -UseModuleFast`
- **Light build** (no docs): `./build.ps1 -Tasks minibuild`
- **Full build with docs**: `./build.ps1 -Tasks build`
- **Run tests**: `./build.ps1 -AutoRestore -Tasks test`
- **Single test**: `Invoke-Pester -Path ./tests/Unit/Public/SomeCmdlet.tests.ps1 -PassThru`
- **Package**: `./build.ps1 -Tasks pack`

VS Code tasks available via `Ctrl+Shift+B`.

## Architecture

### Core Pattern
- All public cmdlets wrap `Invoke-BrevoCall` ([source/Public/Invoke-BrevoCall.ps1](source/Public/Invoke-BrevoCall.ps1))
- Handles HTTP methods, pagination, JSON serialization, and error handling for `https://api.brevo.com/v3`

### Session State
`Connect-Brevo` stores:
- `$script:APIuri` — base API URL
- `$script:APIkey` — credential object

`Disconnect-Brevo` clears them.

### Public Cmdlets Organization
Located in `source/Public/` organized by feature:
- **Contact Management/** — Contact, Folder, List, Attribute, Segment
- **Marketing/** — Email campaigns
- **Account and Settings/** — Domains, Users, Senders
- **Sales CRM/** — Notes, Deals, Companies, Tasks, Pipelines, Attributes, Files

### Build System
- Uses [Sampler](https://github.com/gaelcolas/Sampler) framework
- `build.yaml` defines task workflows
- ModuleBuilder compiles source to `output/`
- GitVersion auto-manages versioning from Git history

## Adding New Cmdlets

1. **Create function**: `source/Public/<Category>/Verb-BrevoNoun.ps1`
   - Include comment-based help (`.SYNOPSIS`, `.DESCRIPTION`, `.PARAMETER`, `.EXAMPLE`)
   - Use `Invoke-BrevoCall` internally (never call `Invoke-RestMethod` directly)

2. **Add tests**: `tests/Unit/Public/Verb-BrevoNoun.tests.ps1`
   - Code coverage threshold: 85% minimum
   - New cmdlets require full test coverage

3. **Update changelog**: Edit `CHANGELOG.md` under `[Unreleased]` section
   - Use Keep a Changelog conventions: `Added`, `Changed`, `Fixed`, `Removed`
   - **Always update CHANGELOG.md after any code/config changes** (same response, not separate)

## Changelog Conventions

**After every code or config change, always update `CHANGELOG.md`** under the `[Unreleased]` section as part of the same response — do not wait to be asked.

- Use **Keep a Changelog** conventions: `Added`, `Changed`, `Fixed`, `Removed`
- Match the existing entry style in the file
- Update immediately in the same PR/response, not as a separate step

## Testing

- **Framework**: Pester (latest)
- **QA tests** (`tests/QA/`) — validate module structure and naming (all public functions require `Brevo` prefix)
- **Unit tests** (`tests/Unit/Public/` and `tests/Unit/Private/`)
- **Linting** — PSScriptAnalyzer runs as part of build pipeline

## CI/CD

GitHub Actions on push to `main`:
- Builds
- Packs
- Publishes to PowerShell Gallery

## Guidelines

### When Making Changes
- Always call `Invoke-BrevoCall`, not `Invoke-RestMethod`
- Ensure functions use `Brevo` prefix
- Write tests for new functionality
- Update CHANGELOG.md immediately

### Code Organization
- Group cmdlets by feature area (Contact Management, Marketing, etc.)
- Follow existing cmdlet patterns
- Use consistent parameter naming as per Brevo API

### Before Opening PR
- Run full test suite
- Verify code coverage ≥ 85%
- Update CHANGELOG.md
- Ensure PSScriptAnalyzer passes
